# Nodetide SMS gateway

Sends verification codes through a USB modem with a SIM. It runs on a machine next to the modem (a home server is
fine, no open ports or public address needed) and only makes **outbound HTTPS requests**:

```
person ──► wallet ──► verification service ──queue──► (long poll, bearer token) ──► this script ──AT──► USB modem ──► SMS
                        nt-verifier.<domain>                                        home server
```

The verification service (`python -m nodetide.verifiers.service`) queues each code instead of sending it itself. This
script fetches the queue (`GET /api/gateway/sms/pending`, a long poll: it returns as soon as something is queued),
sends the messages and reports the result (`POST /api/gateway/sms/{id}/result`), so the wallet can tell the person
whether the SMS left or was refused. Polling over HTTPS was chosen over a message broker: nothing extra to run, works
behind NAT and a firewall, and one request in flight is all there is.

## Safety limits (enforced here, whatever the server asks)

| Limit | Default | Option |
|---|---|---|
| Destination must fully match a mask | `^\+359[0-9]{9}$` (Bulgarian mobile numbers) | `--allow REGEX` |
| Messages per rolling window | **10 per 24 h** | `--max-sms`, `--window-hours` |
| Messages per destination number per window | 3 | `--max-per-number` |
| Text | plain printable ASCII, at most 160 characters | `--max-length` |
| The same message id twice | never sent twice, even if the server offers it again | - |
| Expired messages | not sent | - |

- A send attempt is counted **before** it is made, successful or not, so a flaky modem cannot exceed the cap.
- The counters live in a ledger file (`~/.nodetide-sms-gateway/ledger.json`, mode 0600, numbers stored only as short
  hashes) and survive restarts. A damaged ledger stops the gateway instead of silently resetting the limits;
  deleting the file resets them on purpose.
- A refused message is reported as `rejected` with a reason (`number_not_allowed`, `limit_reached`,
  `number_limit_reached`, `bad_text`, `expired`); the person sees that no SMS is coming and why.
- The service applies its own number mask and rate limits as well (`NODETIDE_PHONE_ALLOWED`, 3 per number / 3 per
  identity / 10 in total per hour), but this script does not rely on that.

## Setup

1. **Modem.** Plug it in; it should appear as a serial port, for example `/dev/ttyUSB0` (stable names:
   `ls /dev/serial/by-id/`). Many USB sticks first show up as a storage device and need `usb_modeswitch`.
   ModemManager grabs such devices and fights over the port: either stop it (`sudo systemctl disable --now ModemManager`)
   or tell it to ignore the modem with a udev rule (`ENV{ID_MM_DEVICE_IGNORE}="1"` for its vendor/product ids).
   Your user needs access to the port (`sudo usermod -aG dialout $USER`, log in again).
2. **Install.** `python3 -m venv venv && venv/bin/pip install pyserial` (Python 3.9 or newer; nothing else is needed).
3. **Check the modem.** `venv/bin/python sms_gateway.py --device /dev/ttyUSB0 --selftest-modem` prints signal, operator
   and network registration. If the SIM asks for a PIN, put it in a file and pass `--sim-pin-file` (a wrong PIN can lock
   the SIM, so it is tried once and never retried).
4. **The token.** The service's `.env` holds `SMS_GATEWAY_TOKEN` (generated by `init.sh`). Copy it to the home server
   into a file only you can read: `install -m 600 /dev/null ~/.nodetide-sms-gateway.token` and paste it in.
5. **Dry run first** (no modem needed): `venv/bin/python sms_gateway.py --server https://nt-verifier.<domain> --token-file ~/.nodetide-sms-gateway.token --dry-run --dry-run-file /tmp/sms.log --once`.
   Start a phone verification in the wallet, run it, and read the code from `/tmp/sms.log` (testing only: the file holds
   the code in clear text).
6. **For real:** drop `--dry-run`, add `--device /dev/ttyUSB0`, run it as a service.

```ini
# /etc/systemd/system/nodetide-sms-gateway.service
[Unit]
Description=Nodetide SMS gateway
After=network-online.target
Wants=network-online.target

[Service]
User=smsgw
SupplementaryGroups=dialout
ExecStart=/opt/nodetide-sms-gateway/venv/bin/python /opt/nodetide-sms-gateway/sms_gateway.py \
    --server https://nt-verifier.example.org --token-file /etc/nodetide-sms-gateway.token \
    --device /dev/serial/by-id/usb-YOUR_MODEM-if00-port0
Restart=always
RestartSec=10
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=read-only
StateDirectory=nodetide-sms-gateway
Environment=HOME=/var/lib/nodetide-sms-gateway

[Install]
WantedBy=multi-user.target
```

(`--state` defaults to `$HOME/.nodetide-sms-gateway/ledger.json`; with the unit above that is the service's state directory.)

## Behaviour worth knowing

- A wrong or revoked token stops the script (it does not retry forever); network errors back off up to a minute.
- If the script dies between sending and reporting, the service offers the message again after two minutes (at most
  twice); the ledger recognises the id and answers "sent" without sending again.
- Numbers are shown masked in the log (`+359*****4567`); codes are never logged.
- `--allow` takes any regular expression, for example `^\+3598[789][0-9]{7}$` for the three Bulgarian mobile prefixes
  only. Set the same on the service with `NODETIDE_PHONE_ALLOWED` (`PHONE_ALLOWED` in the test stack's `.env`).
- Tests: `python/tests/test_sms_gateway.py` (policy, ledger, AT protocol against a scripted serial port, a real run
  against the service).
